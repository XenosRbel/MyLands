# Game frontend
1. Read `client/src/screens/Shell.tsx` and the target screen.
2. Inspect active theme tokens and asset paths.
3. Define the player's primary action.
4. Preserve resource and command state from `useGame()`.
5. Design loading, error, empty, success, and disabled states.
6. Support desktop, touch, and small screens.
7. Support reduced motion and keyboard navigation.
8. Avoid sounds before a user interaction.
9. Add tests for state transitions.
10. Record before-and-after screenshots during browser validation.
