# Harness для Codex и Claude Code

Harness объединяет инструкции, контекст задачи и проверки завершения.
Он хранится в репозитории и использует существующие команды проекта.
Глобальные модели, плагины, разрешения и память остаются пользовательскими.

## Быстрый запуск

Требуется Python ≥3.11.
Общие скрипты рассчитаны на macOS и Linux.
Остальные зависимости перечислены в `Makefile` и проверяются диагностикой.

```bash
rtk make harness-context
rtk make harness-doctor
rtk make harness-test
rtk make harness-check
```

RTK сокращает вывод, но не требуется самому harness.
Если RTK отсутствует, запускай команды без префикса `rtk`.

Из вложенного каталога используй корень репозитория:

```bash
rtk make -C "$(git rev-parse --show-toplevel)" harness-context
```

Диагностика ничего не устанавливает.
При отсутствующих клиентских зависимостях выполни `npm ci` в `client/`.
При отсутствующей тестовой БД запусти `make db` с подходящими `PGBIN` и `PGDATA`.
Скрипт `scripts/dev-postgres.sh` по умолчанию предполагает Linux.
На macOS укажи каталог установленного сервера PostgreSQL через `PGBIN`.
Клиентского пакета libpq недостаточно для запуска сервера.

Для отдельной тестовой БД задай `RF_TEST_ADMIN_URL` в окружении.
Тесты создают базы `rf_test_*` и пересоздают их схему `public`.
Используй изолированный PostgreSQL, предназначенный для тестов.
Не сохраняй URL с паролем в отслеживаемых файлах.

Альтернатива для локальных тестов — отдельный Docker-контейнер PostgreSQL 16:

```bash
rtk docker run --rm -d --name realmforge-agent-tests -e POSTGRES_HOST_AUTH_METHOD=trust -p 127.0.0.1:55432:5432 postgres:16
rtk proxy env RF_TEST_ADMIN_URL='postgres://postgres@127.0.0.1:55432/postgres?sslmode=disable' make harness-doctor
rtk proxy env RF_TEST_ADMIN_URL='postgres://postgres@127.0.0.1:55432/postgres?sslmode=disable' make harness-check
rtk docker stop realmforge-agent-tests
```

Дождись готовности PostgreSQL перед проверками.
Выбери другой порт, если `55432` занят.
Этот контейнер предназначен только для локальных тестов.
Compose-сервис `db` проекта не публикует порт на хост по умолчанию.

## Текущая задача

Карточки задач остаются в `tasks/`.
Указатель задачи и журнал проверок хранятся в игнорируемом каталоге `.harness/`.

```bash
rtk proxy mkdir -p .harness
rtk proxy sh -c 'printf "%s\n" tasks/T-032.md > .harness/current-task'
```

Указатель должен содержать относительный путь существующей карточки.
Контекст показывает ошибочный указатель явно.
SessionStart выводит ветку, изменения, текущую задачу и обязательные документы.

## Подключение клиентов

| Инструмент | Инструкции | Конфигурация событий |
|---|---|---|
| Codex | `AGENTS.md` → `AGENT.md` → `.agents/HARNESS.md` | `.codex/hooks.json`, `.codex/config.toml` |
| Claude Code | `.claude/CLAUDE.md` → `.agents/HARNESS.md`; инженерные правила `AGENT.md` | `.claude/settings.json` |

Оба клиента вызывают `scripts/harness/harness.py hook`.
Обработчик читает одно JSON-событие из stdin.
Рабочий каталог события определяет активный checkout, включая worktree.

Проверены установленные версии Codex CLI 0.147.0 и Claude Code 2.1.308.
Codex CLI сообщает `hooks: stable, true`.
Настройки Claude используют `onFailure: block` для PreToolUse.
Этот параметр требует Claude Code ≥2.1.295 согласно [документации Claude Code](https://code.claude.com/docs/en/hooks).

После изменения конфигурации открой новую сессию клиента.
В Codex открой `/hooks` и проверь определения перед предоставлением доверия.
Codex пропускает недоверенные или изменённые хуки.
Доверие нельзя считать настроенным после одного запуска Python.
Правила загрузки описаны в [документации Codex](https://learn.chatgpt.com/docs/hooks).

Не отключай проверку доверия ради автоматического запуска.
Не копируй эти же хуки в глобальные настройки: иначе проверки могут выполняться дважды.
Глобальные и plugin-хуки продолжают действовать согласно настройкам клиента.

## События

| Событие | Действие | Таймаут клиента |
|---|---|---|
| SessionStart | Контекст репозитория | 10 с |
| PreToolUse | Проверка прямых правок и распознаваемых shell-команд | 10 с |
| PostToolUse | `gofmt` изменённых Go-файлов; проверка пробелов Markdown | 30 с |
| Stop | `make harness-check` при изменённом рабочем дереве | 720 с |

Stop ограничивает общую проверку 660 секундами.
Таймаут завершает также дочерние процессы проверки.
Полный вывод записывается в `.harness/check.log`.
Красная проверка возвращает `decision: block` с объяснением.
Повторный Stop с `stop_hook_active=true` пропускает проверку и сообщает, что завершение не подтверждено.
Это предотвращает бесконечное продолжение при недоступной БД или другом внешнем блокере.
Такой выход не отменяет критерии готовности из `AGENT.md`.

Чистое рабочее дерево не запускает полный набор при каждом ответе.
Перед коммитом всё равно требуется `make harness-check`.
Проверка E2E запускается отдельно для пользовательских потоков.

Форматтер TypeScript не добавлен: проект не содержит согласованной конфигурации форматирования.
Проверка Markdown обнаруживает одиночные завершающие пробелы; два пробела разрешены как перенос строки.
Она не проверяет язык, смысл, ссылки или длину предложений.

## Защищённые операции

- Прямые изменения `.env*`, кроме `.env.example`, блокируются.
- Прямые изменения ключей `.pem`, `.key`, `.p12`, `.pfx` блокируются.
- Миграции, присутствующие в `HEAD`, считаются защищённым консервативным базисом.
- Новые миграции доступны для правки, включая staged-файлы.
- `api/openapi.yaml` изменяется штатным генератором, а не прямой правкой агента.
- Прямые изменения `.git`, `dist`, `node_modules`, `server/bin` блокируются.
- Codex `apply_patch` проверяет исходные пути и назначения `Move to`.
- Распознаваемые force push, hard reset и forced clean блокируются.
- Рекурсивное удаление внутри репозитория или его родителя блокируется.
- Удаление отдельного временного каталога вне репозитория разрешено.
- Коммиты в `main`, `master`, `release/*` и detached HEAD блокируются.

Обычные feature-ветки разрешены; имя `dev` не требуется.
Генерацию OpenAPI выполняй через `server/api/gen_openapi.py` согласно `AGENT.md`.

Это вспомогательная защита от ошибок, а не песочница.
Произвольные shell-программы, перенаправления, интерпретаторы и неподдерживаемые инструменты могут обходить файловую проверку.
Поддержка событий зависит от клиента, его версии и доверия.
Разрешения клиента и ревью diff остаются обязательными.

## Skills и MCP

Существующие skills переиспользуются относительными симлинками между `.agents/skills/` и `.claude/skills/`.
Копии содержимого и отдельные инструкции игровых правил не создаются.
Сохраняй симлинки при клонировании и переносе репозитория.

В текущей среде codebase-memory-mcp уже настроен глобально в обоих клиентах.
Проектный harness не создаёт второе подключение.
Новый разработчик устанавливает сервер отдельно и подключает его в каждом клиенте:

```bash
rtk proxy codex mcp add codebase-memory-mcp -- codebase-memory-mcp
rtk proxy claude mcp add --transport stdio --scope local codebase-memory-mcp -- codebase-memory-mcp
```

Если подключение уже существует, пропусти соответствующую команду.
Вызови MCP `index_status` для текущего проекта.
Если индекса нет, вызови `index_repository` с абсолютным путём checkout.
Проверь результат перед поиском кода.
Диагностика harness проверяет наличие исполняемого файла, но не подтверждает живое MCP-подключение.

## Самопроверка

`make harness-test` запускает автономные тесты без аккаунтов агентов и PostgreSQL.
Тесты создают временные Git-репозитории и не меняют настройки основного checkout.
Проверяются обе реальные строки запуска хуков, включая красный Stop.
Проверяются пути с пробелами, вложенный каталог, миграции, секреты, apply_patch и таймаут процесса.

`make harness-check` последовательно запускает:

1. `make harness-test`.
2. `make lint`.
3. `make test` с обязательной БД и Go race detector.
4. `make packs`.

При ошибке последующие команды не выполняются.
Не трактуй непройденные команды как успешные.
Результаты текущей настройки записаны в [T-032](../tasks/T-032.md).

## Роль Principal Architect

Общая ответственность описана в `.agents/roles/principal-architect.md`.
Роль исследует архитектуру, производительность, надёжность и стоимость эксплуатации.
Она возвращает рекомендации и план измерений без реализации изменений.
Основной агент записывает документы, запускает согласованные испытания и выполняет completion gate.

| Клиент | Определение | Использование |
|---|---|---|
| Codex | `.codex/agents/principal-architect.toml` | Попроси использовать `principal_architect` в новой сессии |
| Claude Code | `.claude/agents/principal-architect.md` | `claude --agent principal-architect` или явное делегирование |
| GitHub Copilot | `.github/agents/principal-architect.agent.md` | Выбери профиль Principal Architect, когда он доступен в репозитории |

Модель наследуется от клиента; роль не устанавливает платную модель автоматически.
Для локальных клиентов указан высокий уровень reasoning, поддерживаемый выбранной моделью.
Новые определения требуют загрузки клиентом; реальные сессии роли пока не проверены.

Codex наследует разрешения родительской сессии.
Его адаптер отключает shell и запрос расширения разрешений; запрет правок также задан инструкцией.
Это не отдельная read-only песочница.
Формат TOML и наследование описаны в [документации Codex](https://learn.chatgpt.com/docs/agent-configuration/subagents).

Claude использует список инструментов чтения, поиска и отдельных MCP-запросов.
Инструменты записи, shell и делегирования в его список не включены.
Формат описан в [документации Claude Code](https://code.claude.com/docs/en/sub-agents).

GitHub-профиль предназначен для custom agents GitHub Copilot и отключает автоматический выбор роли.
Для появления в GitHub файлы нужно закоммитить и отправить в доступную клиенту ветку.
Выбор партнёрского провайдера Claude или Codex не доказывает загрузку Copilot-профиля.
Подключение MCP и совместимость конкретного облачного агента проверяются отдельно.
Формат описан в [документации GitHub](https://docs.github.com/en/copilot/reference/custom-agents-configuration).
