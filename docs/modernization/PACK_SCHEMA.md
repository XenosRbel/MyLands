# Расширение схемы Game Pack для My Lands (ML-D01)

## 1. Область

1. Документ описывает необязательные поля пака для My Lands.
2. Реализация: `server/internal/pack/types_mylands.go` и `validate_mylands.go`.
3. Пример: `packs/mylands-sample/pack.json`.
4. Версия формата не меняется. `formatVersion` остаётся 1.
5. Все поля имеют `omitempty`. Старые паки проходят проверку без изменений.
6. Неизвестные поля отклоняются на всех уровнях, включая значения `Num`.

## 2. Правила

1. Данные игры лежат в паке. Движок не знает имён ресурсов, зданий и кристаллов.
2. Каждый идентификатор уникален среди всех сущностей пака.
3. Удаление или переименование идентификатора требует записи в `migrations`.
4. Значения со статусом `PROPOSED` задаёт автор пака. Источник их не подтверждает.

## 3. Поле Num

Числовой параметр имеет два вида записи.

| Вид | Пример | Смысл |
|---|---|---|
| Число | `50` | Одно значение для всех рас |
| Объект | `{"base": 50, "races": {"knights": 100}}` | Базовое значение и значения по расам |

1. Идентификаторы в `races` должны существовать в списке рас.
2. Расы без записи получают значение `base`.
3. Источник пишет такие значения как `Раса:значение`.

## 4. Кристаллы: `crystals`

| Поле | Тип | Правило |
|---|---|---|
| `id` | строка | Идентификатор сущности |
| `tier` | целое | Не меньше 1 |

Количества кристаллов указаны в `buildingTables[].levels[].crystals`. Это значения `PROPOSED`.

## 5. Таблицы зданий: `buildingTables`

| Поле | Тип | Правило |
|---|---|---|
| `building` | строка | Идентификатор здания из `buildings` |
| `levels` | список | От 1 до 9 строк. Уровни идут подряд с 1 |

Поля строки уровня:

| Поле | Тип | Правило |
|---|---|---|
| `level` | целое | Равно номеру строки |
| `cost` | `resourceId -> целое` | Ключ должен быть ресурсом. Значение не меньше 0 |
| `crystals` | `crystalId -> целое` | Ключ должен быть кристаллом. Значение не меньше 0 |
| `timeSeconds` | целое | Не меньше 0 |
| `effects` | `имя -> Num` | Имя в camelCase. Например `kills`, `carrierCapacity` |
| `overrides` | `profileId -> (имя -> Num)` | Значения для профиля сервера. Профиль должен существовать. Имя в camelCase |

1. Отсутствующий ключ в `cost` означает «не требуется».
2. На одно здание допустима одна таблица.
3. `overrides` заменяет только указанные эффекты. Остальные берутся из `effects`.
4. Если у здания есть таблица, поля `cost` и `time` записи в `buildings` могут быть пустыми. Таблица главнее.

## 6. Профили серверов

`paramDefs` объявляет параметр и диапазон.

| Поле | Правило |
|---|---|
| `id` | Идентификатор сущности |
| `min`, `max` | `min` не больше `max` |
| `default` | В пределах `min` и `max` |

`serverProfiles` задаёт множители.

| Поле | Правило |
|---|---|
| `id` | Идентификатор профиля |
| `multipliers` | `paramId -> число`. Параметр должен быть объявлен. Значение в пределах `min` и `max` |

Пак не зависит от таблиц базы. Идея повторяет `server_param_defs` из `DB_DESIGN.md`.

## 7. Юниты: `unitDefs`

| Поле | Правило |
|---|---|
| `id` | Идентификатор сущности |
| `category` | Идентификатор категории |
| `level` | От 1 до 4 |
| `params` | `имя -> Num`. Например `attackMin`, `attackMax`, `health`, `upkeep`, `population`, `rating` |
| `cost` | `resourceId -> целое` |
| `names` | `raceId -> LocText`. Ключ `monsters` задаёт имя монстра. Расы и локали должны существовать |
| `overrides` | `profileId -> {params, cost}` |

1. Ключ в `overrides` должен быть профилем сервера.
2. Переопределение заменяет только указанные параметры.
3. Отдельные поля для экономического сервера не нужны.

## 8. Платные услуги: `services`

| Поле | Правило |
|---|---|
| `id` | Идентификатор услуги |
| `group` | Идентификатор группы |
| `proposed` | `true`, если источник не подтверждает значения |
| `levels` | Не пусто. Каждый уровень: `price` не меньше 1, `durationSeconds` не меньше 1 |

1. Цена выражена в ресурсе `params.premiumResource`.
2. Если услуги есть, `params.premiumResource` должен называть существующий ресурс.
3. Цены остаются в паке. Таблица `service_defs` их не хранит.

## 9. Геометрия карты: `geometry`

| Поле | Значение для My Lands | Правило |
|---|---|---|
| `empireWidth` | 90 | Целое не меньше 1 |
| `empireHeight` | 30 | Целое не меньше 1 |
| `kingdomWidth` | 9 | Целое не меньше 1 |
| `kingdomHeight` | 9 | Целое не меньше 1 |
| `proposed` | `true` | Значения предложены автором пака |

1. Королевство имеет адрес `x-y`. Поле имеет адрес `x-y-n`.
2. Полей в королевстве: `kingdomWidth * kingdomHeight`. Для 9 и 9 это 81.
3. Поле `geometry` отделено от `params.mapWidth` и `params.mapHeight`.

## 10. Проверка

1. Тесты: `server/internal/pack/mylands_test.go`.
2. Команда: `make packs`.
3. Пример содержит таблицы Fortification и Temple из `tables-dom.txt`.
4. Количества кристаллов в примере — `PROPOSED`. Источник даёт только цвета.

## 11. Пак `packs/mylands` (ML-D02, ML-D03, ML-D04)

1. Пак создаёт `scripts/gen_mylands_pack.py` из `tables-dom.json` и `units-roster.csv`.
2. Проверка актуальности: `python3 scripts/gen_mylands_pack.py --check`.
3. Здания лежат в `buildings` и `buildingTables`. Идентификаторы клановых вариантов имеют суффикс `_kz`.
4. Таблица простой башни — `tower`. Таблица магической башни — `magic_tower`.
5. Склад клана — `clan_warehouse`. Резервация клана — `clan_reservation`.
6. Юниты: `{категория}_{уровень}`, `{категория}_monster_{уровень}`, `{категория}_castle_{уровень}`.
7. Профили `economic`, `tactical`, `heroic` не имеют множителей. Источник их не задаёт.
8. Пустая и нулевая ячейка источника не попадает в пак. Список `UNKNOWN` лежит в `strings` под ключами `unknown.NN`.
9. Тесты: `server/internal/pack/mylands_pack_test.go`.
