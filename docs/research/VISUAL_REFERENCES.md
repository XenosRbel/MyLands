## Verified interface patterns

1. A compact resource strip sits across the top of the game.
2. A large settlement or world scene occupies the center.
3. The original uses a bottom action bar with portraits and counts.
4. A city selection control stays near the main frame.
5. Building panels use parchment content against darker world scenes.
6. Research uses illustrated nodes, connections, and progress.
7. A detail panel displays requirements and action controls.

## Ashen Crowns adaptation

- Retain the resource bar.
- Present the world before the management panels.
- Provide a bottom command dock on desktop.
- Use a compact left icon rail for secondary navigation.
- Present buildings in an integrated tray and detail dialog.
- Display army units in a roster with large selected-unit details.
- Show hero selection, equipment, and skills on one screen.
- Present research as connected levels and category branches.
- Use illustrated location inspection for the map.

## Design constraints

The user approved the muted palette.
Do not introduce bright gold glows.
Do not use third-party screenshots as in-game sprites.
Do not change gameplay mechanics during visual-only edits.
Keep all controls accessible by keyboard.
Keep mobile layouts usable without horizontal overflow.

## Visual acceptance

Capture screenshots from an actual game session.
Compare layout regions with the reference sources.
Record every observed difference and proposed correction.
Fix each reproducible visual defect.
Retest the same viewport after each fix.
Do not declare visual equivalence before human review.
