# Общий harness для Codex и Claude Code

Дата: 2026-11-01.
Статус: дизайн одобрен пользователем 2026-11-01.
Задача: [T-032](../../../tasks/T-032.md).

## Назначение

Создать воспроизводимую рабочую среду агентов в текущей ветке.
Использовать приложенное описание Claude Code как ориентир.
Адаптировать настройки к Realmforge и возможностям каждого инструмента.

## Рассмотренные подходы

1. Общий harness внутри репозитория. Правила и проверки общие; настройки инструментов отдельные.
2. Дополнительная глобальная настройка. Она затрагивает другие проекты и требует отдельных решений.

Пользователь выбрал первый подход.
Изменения остаются в ветке `improve/game-experience-audit-20261031`.

## Общая основа

- Сохранить `AGENT.md` и ссылку `AGENTS.md` как источник инженерных правил.
- Подключить общую инструкцию harness из инструкций обоих инструментов.
- Использовать существующие карточки `tasks/T-*.md`.
- Хранить указатель текущей задачи в игнорируемом локальном состоянии.
- Переиспользовать существующие проектные skills через поддерживаемое обнаружение или ссылки.
- Сохранить приоритет codebase-memory-mcp для поиска кода.
- Не требовать делегирования для каждой задачи.

## Команды

Предложенные цели `Makefile`:

- `harness-context`: ветка, изменения, текущая задача и ссылки на обязательные документы.
- `harness-doctor`: наличие инструментов, корректность конфигурации и доступность зависимостей.
- `harness-test`: проверки адаптеров событий, защиты файлов и обработки ошибок.
- `harness-check`: тесты harness, `make lint`, `make test` и `make packs`.

Команды запускаются из любого каталога репозитория.
Проверки возвращают ненулевой код при ошибке.
Проверки не устанавливают пакеты и не запускают сервер автоматически.
Для пользовательских изменений по-прежнему обязателен `make e2e` с работающим сервером.

## Настройки инструментов

### Claude Code

- Сохранить существующий `.claude/CLAUDE.md` и расширить его ссылкой на общий процесс.
- Добавить проектные настройки и тонкие адаптеры событий.
- SessionStart выводит контекст репозитория.
- PreToolUse проверяет поддерживаемые операции записи и опасные команды.
- PostToolUse форматирует поддерживаемые файлы после изменения.
- Stop запускает общую проверку завершения.
- Повторный Stop после блокировки не создаёт бесконечный цикл.

### Codex

- Добавить проектную конфигурацию `.codex/`.
- Проверить схему и возможности установленной версии перед выбором параметров.
- Подключить общие команды через поддерживаемые хуки, если они доступны.
- При отсутствии нужного события документировать ручную команду и фактическое ограничение.
- Не выдавать инструкцию агенту за техническую блокировку.

## Защита и совместимость

- Запрещать очевидные разрушительные команды, затрагивающие репозиторий.
- Не блокировать обычное удаление временных файлов вне репозитория.
- Не привязывать разрешённую ветку к `dev` из чужого проекта.
- Защищать секреты и выпущенные миграции от прямого изменения.
- Разрешать новые миграции согласно действующему append-only правилу.
- Сохранить штатную генерацию `api/openapi.yaml`.
- Не объявлять разбор shell-команды полноценной песочницей.
- Не расширять разрешения агентов автоматически.

## MCP, модели и глобальная среда

## Решения исполнителя

Исполнитель выбирает минимальный формат общих скриптов после проверки доступных интерпретаторов.
Исполнитель выбирает поддерживаемые параметры по установленным версиям и официальной документации.
Новые настройки не меняют игровые правила, HTTP API или схему базы данных.
